# 배포하고 현장에서 확인하기

이 문서는 두 부분입니다. **1부는 책상에서 한 번** 하는 배포, **2부는 꿈제작소 현장에서 폰으로** 하는 확인입니다.

---

# 1부. Cloudflare Pages 배포 (약 20분, 무료)

## 왜 Cloudflare인가

무료 플랜에 상업적 이용 제한이 없습니다. Vercel 무료 플랜은 비상업적 개인 용도로 제한되어 있어 이 프로젝트에는 쓸 수 없습니다.

## 순서

### 1. 계정 만들기

[dash.cloudflare.com](https://dash.cloudflare.com/sign-up) 에서 가입합니다. 신용카드는 필요하지 않습니다.

### 2. 프로젝트 연결

왼쪽 메뉴에서 **Workers & Pages** → **Create** → **Pages** 탭 → **Connect to Git** 을 선택합니다.
GitHub 계정을 연결하고 `goyang-dream-factory-ver3` 저장소를 고릅니다.

### 3. 빌드 설정 입력

이 세 칸만 채우면 됩니다. 나머지는 기본값 그대로 둡니다.

| 칸 | 넣을 값 |
|---|---|
| Framework preset | `None` |
| Build command | `pnpm install --no-frozen-lockfile --ignore-scripts && DEPLOY_BASE=/ pnpm exec vite build --config vite.static.config.ts` |
| Build output directory | `dist-static` |

Production branch는 `main`으로 둡니다.

### 4. 배포

**Save and Deploy** 를 누르면 2~4분 뒤 `프로젝트명.pages.dev` 주소가 나옵니다. 이 주소가 게임 주소입니다.

이후에는 `main` 브랜치에 코드가 올라갈 때마다 자동으로 다시 배포됩니다.

## 배포 직후 확인 (책상에서 30초)

PC 브라우저로 아래 두 개만 열어봅니다.

1. `https://프로젝트명.pages.dev/` → 게임 화면이 나오는지
2. `https://프로젝트명.pages.dev/diag` → 진단 화면이 나오는지

**주의: 이미지 자산이 아직 없어서 캐릭터는 CSS 픽셀 아트로 보입니다.** 이건 정상입니다. 원본 이미지를 넣는 방법은 [`client/public/game/README.md`](../client/public/game/README.md)에 있습니다.

# 2부. 현장 확인 (꿈제작소에서, 폰으로)

## 준비물

- 아이폰 1대, 안드로이드폰 1대 (**둘 다 필요합니다** — 나침반 동작이 다릅니다)
- 배포된 주소

## 왜 진단 화면부터인가

폰에서는 개발자도구를 열 수 없어서, 문제가 생겨도 원인을 알 수 없습니다. 진단 화면(`/diag`)이 센서 값을 화면에 직접 띄우고, 그 결과를 텍스트로 복사할 수 있게 해줍니다.

**"안 되네요" 대신 복사한 결과를 그대로 전달해 주세요.** 그러면 원인을 특정할 수 있습니다.

## 순서 — 각 폰마다 반복

### A. 진단 화면 (건물 안에서, 반경 180m 이내)

`https://프로젝트명.pages.dev/diag` 접속 → 버튼을 **위에서 아래로 순서대로** 누릅니다.

| 단계 | 눌러야 할 것 | 정상이면 |
|---|---|---|
| 1 | **카메라 켜기** | 권한 팝업 → 허용 → 화면에 카메라 영상이 보임 |
| 2 | **위치 확인 시작** | 권한 팝업 → 허용 → 좌표가 나오고 "**반경 안**"으로 표시됨 |
| 3 | **나침반 확인 시작** | (아이폰은 권한 팝업) → **폰을 제자리에서 한 바퀴 천천히 돌리면 "계산된 방위" 숫자가 바뀜** |
| 4 | **결과 복사하기** | 복사됨 |

**3번이 이번 테스트의 핵심입니다.** 폰을 돌렸을 때 숫자가 바뀌지 않으면 게임의 AR 방향 찾기가 작동하지 않습니다.

복사가 안 되면 아래 상자의 글을 길게 눌러 직접 선택해 복사하시면 됩니다.

### B. 게임 화면

`https://프로젝트명.pages.dev/` 접속 → 카메라 권한 허용 → AR 탐색을 시도합니다.

확인할 것:

- [ ] 카메라 배경이 보이는가
- [ ] 청년이 나타나는가
- [ ] **폰을 좌우로 돌리면 "오른쪽/왼쪽으로 방향을 돌려 보세요" 안내가 나오고, 맞는 방향에서 청년이 보이는가**
- [ ] 대화 선택지를 누르면 카드가 획득되는가
- [ ] 하단 5개 탭이 겹치지 않고 눌리는가
- [ ] 세로 화면에서 글자나 버튼이 잘리지 않는가

### C. 반경 밖에서도 한 번

건물에서 200m 이상 떨어진 곳에서 게임에 접속해, **"반경 밖" 안내가 제대로 나오는지** 확인합니다. 여기서 카메라가 열리면 지오펜스가 작동하지 않는 것입니다.

## 전달해 주실 것

1. `/diag`에서 복사한 결과 — **아이폰·안드로이드 각각**
2. 위 B의 체크박스 중 안 되는 항목
3. 이상한 화면이 있으면 스크린샷

이 세 가지가 있으면 대부분의 문제를 코드에서 특정할 수 있습니다.

## 자주 나오는 문제

| 증상 | 원인 | 대응 |
|---|---|---|
| 카메라·위치 권한 팝업이 안 뜬다 | HTTPS가 아님 | `https://` 주소로 접속. 진단 화면 맨 위에 빨간 경고가 뜹니다 |
| 권한을 한 번 거부한 뒤로 안 뜬다 | 브라우저가 거부를 기억함 | 주소창 자물쇠 아이콘 → 권한 초기화, 또는 브라우저 설정에서 해당 사이트 권한 삭제 |
| 실내에서 좌표가 크게 튄다 | 실내 GPS 오차 | 정상입니다. 진단 화면의 "정확도" 값을 기록해 주세요 |
| 폰을 돌려도 방위 숫자가 안 바뀐다 | 나침반 미지원 또는 권한 문제 | 진단 결과를 그대로 전달해 주세요. `deviceorientationabsolute` 이벤트 수가 판단 근거입니다 |
| 게임 진행이 사라졌다 | 진행도가 브라우저에만 저장됨 | 현재 설계상 그렇습니다. 상시 운영으로 가면 별도 대응이 필요합니다 |

## 반경 밖에서 체험만 해보려면

주소 뒤에 `?test=1`을 붙이면 GPS 반경 검사를 건너뛰고 가상 GPS 구역으로 체험할 수 있습니다.

```
https://프로젝트명.pages.dev/?test=1
```

데모나 사무실 확인용입니다. 경품을 운영하게 되면 이 기능은 분리해야 합니다.
